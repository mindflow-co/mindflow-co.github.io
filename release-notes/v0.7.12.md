# Mindflow v0.7.12

**Released:** 2026-07-23

A major accuracy release for meetings: this update fixes the bug that made meeting participants appear to constantly interrupt each other in transcripts, stops the app from inventing extra speakers, and closes most of the quality gap between meeting transcripts and dictation.

## What's new
- **Meeting transcripts now read in true chronological order.** Previously, your microphone and the other participants' audio were kept on separate internal clocks that slowly drifted apart, and the transcript was assembled in whatever order processing finished. The result was conversations that looked like everyone was talking over each other — even in meetings with perfectly polite turn-taking. Both audio sources now share a single clock, and every transcript is sorted by when things were actually said.
- **Noticeably better meeting transcription quality.** Meeting audio used to be sliced into rigid 15-second blocks, which routinely cut speakers off mid-word and caused garbled or repetitive text ("yeah yeah yeah…"). Audio is now split at natural pauses in speech, so each piece sent to the recognizer is a complete thought — the same reason dictation has always been more accurate. Meetings and dictation should now be much closer in quality.
- **Arabic Pro is now the default engine for Arabic.** Benchmarked on real Egyptian Arabic recordings, Arabic Pro clearly outperformed the previous default, so new Arabic meetings and dictation now recommend it automatically. You can still pick any other model in Settings → Models.

## Fixes
- Meetings no longer show more speakers than were actually present. The speaker-identification step sometimes split one person into two or three "speakers" based on a stray "Okay" or a short remark; those fragments are now folded back into the correct speaker, so a three-person stand-up shows exactly three names.
- A recording no longer stops itself prematurely when the recognizer returns a run of short empty results — the safety cutoff now measures actual lost audio time rather than counting chunks, which matters now that chunks vary in length.

## Under the hood
- Transcript timestamps are now anchored to a single monotonic session clock across both audio sources, and every rendered transcript (including regenerated ones after speaker identification) is time-sorted.
- The live session log that AI-assistant integrations read is unchanged, so Claude Code and other MCP clients keep working without any reconfiguration.
