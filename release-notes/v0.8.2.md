# Mindflow v0.8.2

**Released:** 2026-08-20

## Fixes

- **A speaker pass that fails no longer destroys the audio it was working on.** When a meeting stops, its audio is moved into a working folder for the speaker pass, and until that pass succeeds that folder holds the only copy of the separated per-channel audio the pass runs on — and, if you have turned "Save audio recordings" off, the only copy of that meeting's audio at all. If the pass threw an error — no network during the first-run model download, memory pressure, another app holding the machine's neural engine, a file it could not read — Mindflow used to delete that folder as part of tidying up, so a single failure permanently destroyed the audio of a meeting you had just finished recording. A failed pass now leaves the folder alone and tries again at the next launch, up to three attempts in total. After that it stops retrying but still keeps the audio, and only the ordinary case — a folder with no audio left in it — is cleaned up. Nothing about a failure deletes audio any more.
- **Starting a new recording no longer wipes audio left behind by the previous one.** If Mindflow stopped during a recording rather than after it — a crash, a force quit, the machine going down — that session's audio stayed in the live capture folder, because audio is only moved somewhere protected after a transcript has been written, and a recording that dies partway through never writes one. The next recording then cleared those files before it started. Leftover audio is now moved aside and kept instead. Be clear about what that does and does not do: there is no transcript for these recordings, so there is nothing for Mindflow to finish and nothing new appears in your meeting list. The audio is preserved in `~/.local/share/mindflow/diarize-queue/`, in a folder named for the time it was rescued, so it can be recovered by hand. It is kept for 30 days. Files too short to contain anything — under a second of audio, which is what an interrupted recording that never captured a buffer leaves behind — are still cleared.
- **The launch-time cleanup of the live folder no longer removes leftover recordings either.** The same audio was exposed to a second sweep: at launch Mindflow clears working files in that folder once they are more than an hour old, which meant a session's audio was deleted simply for being old, whether or not a new recording had started. That sweep now rescues session audio first, regardless of age, and only then clears what is genuinely scratch — a recording is not junk because it is old.
- **Mindflow now tells you when it has kept a recording it could not finish.** Keeping audio rather than deleting it is the right trade, but it is only a fair one if you know it happened — otherwise a broken setup quietly accumulates gigabytes with nothing to explain them. When Mindflow starts up and finds recordings it kept, it now says so in the menu bar popover: how many, why, and where they are. The three reasons are distinct and it says which applies — speaker identification ran out of attempts, the audio is missing its system channel, or Mindflow cannot tell which meeting the audio belongs to. Each recording is kept for at least 30 days from when it was set aside.

- **Quitting during speaker identification now waits for the last pass, not the first.** Mindflow blocks quitting while speaker identification is running, because that pass rewrites a transcript in place. When several passes were queued — a few recovered recordings at launch, or a new meeting stopped while an earlier pass was still running — the block was lifted as soon as the first one finished, so quitting during the remainder could interrupt a transcript mid-rewrite. It now lifts only when every queued pass is done.
- **Speaker identification that resumes at launch is now visible.** When Mindflow picked a pass back up on launch, it rewrote the transcript with no indication that anything was happening: an open transcript would change under you with no progress shown, and the meeting list was not refreshed afterwards. The "Identifying speakers…" indicator now follows the recovered meeting through the queue, and the list refreshes as each one completes.
- **An opt-in per-channel audio copy is no longer lost to a silent failure.** With "Keep separated audio for re-processing" switched on, those copies were only written when the speaker pass succeeded — so the one case where you would most want them, a pass that failed, produced nothing. They are now written on failure too. And on success, Mindflow only deletes the working audio once it has confirmed the kept copy is actually there and complete; previously the copy was attempted and the originals deleted regardless, so a copy that failed quietly took the originals with it.

## Under the hood

- The 30-day clock on kept audio is read from the recording's own timestamp rather than from the folder's last-modified date. Recording an attempt touches the folder, so a last-modified clock would have quietly restarted the retention window on every retry and turned "kept for 30 days" into "kept forever".
- The attempt counter is written to disk before each pass begins, not after it fails. The failure this bound exists to contain is a hard crash inside the speaker model's loading code, which never gets the chance to record anything on the way out; counting afterwards would leave that crash repeating at every launch indefinitely.
- The rule deciding what may be deleted is a pure function with no file access of its own, so it can be exercised exhaustively over every combination of inputs rather than sampled. The parts that do touch the disk — the attempt counter and the rescue of leftover audio — have their own tests against real files. It is the kind of change where being sure matters more than being quick.
