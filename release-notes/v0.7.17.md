# Mindflow v0.7.17

**Released:** 2026-08-19

## Fixes

- **A speaker pass interrupted by the app closing no longer costs you the recording.** When a meeting stops, Mindflow writes the transcript and then moves that meeting's audio into a working folder so it can work out who was speaking. If the app closed before that pass finished — a crash, a forced quit, a machine restart — the next launch wiped the whole folder, and what it wiped was the only copy of the audio, so the pass could never be run again. It was worst for long meetings, where the pass takes longest. That sweep is gone. Staged audio now carries a note of which meeting it belongs to, so on the next launch Mindflow can pick the pass back up and finish it on its own — provided that meeting's transcript is still on disk and enhanced speaker identification is still switched on in Settings. When either of those is not true, or when the audio cannot be matched to a meeting at all, Mindflow leaves the audio where it is and says so in its logs instead of deleting it. Audio it cannot match is kept for 30 days and cleared after that.

## Known limitation in this version

- **A speaker pass that *fails* still deletes the audio it was working on.** The recovery above covers the app closing before the pass finishes. It does not cover the pass itself throwing an error — no network during the first-run model download, memory pressure, a file it cannot read. In that case this version removes the working folder as part of tidying up, and the staged audio goes with it. Your transcript is unaffected — it is written before the pass starts. What is lost is the separated per-channel audio, and with it any chance of identifying speakers for that meeting later. If "Save audio recordings" is on, as it is by default, the playback recording for that meeting was already written next to the transcript and survives, so you can still listen back; but that file is a recompressed mix of both channels, not the separated audio a re-run would need. If you had turned that setting off, nothing of the audio remains. This is fixed in v0.7.18.

## Under the hood

- Audio staged for speaker identification now carries a small manifest naming the meeting it belongs to, which is what makes the recovery above possible — previously that link existed only in memory and was lost the moment the app closed. Audio left behind by earlier versions carries no manifest, so it falls into the "kept, not finished" case above.
- The scope of this fix is narrower than it first sounds, and it is worth being precise about. A recording is only staged into that working folder *after* its transcript has been exported, which is the last thing a normal stop does. A recording that never got that far — the app died while it was still recording — was never in the folder, so nothing here protects it. That case is fixed in v0.7.18.
- Arabic transcription now records two engineering diagnostics for each segment: the decoder's own average confidence, and whether the anti-repetition guard fired. These go into the machine-readable transcript sidecar and a developer command-line tool; nothing in the app shows them, and they are deliberately not a quality score — the investigation that added them found the confidence figure reads *higher* on exactly the looping segments the guard exists to cut. They exist so that the engine's behaviour can be measured after the fact, instead of having to be reproduced first.
