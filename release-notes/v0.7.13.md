# Mindflow v0.7.13

**Released:** 2026-07-27

## Fixes

- The segment count saved with each meeting was too high. Mindflow filters out speech-recognition artefacts as it transcribes — phrases the model hallucinates during silence, like "Thanks for watching" — and each of those removals was being counted as if it were a real segment. A 55-minute meeting with 549 segments was recorded as having 557. The count now reflects only the segments actually kept, so it matches what you see in the transcript.
- Meetings started from the menu bar or the ⌃⌥R shortcut were not getting a crash-recovery file. Mindflow periodically saves an in-progress copy of a meeting so nothing is lost if the app or your Mac goes down mid-recording — but that only happened for meetings your AI assistant started. Recordings you began yourself had no safety net, and the failure was silent. Every meeting now gets one, however it was started.
- Your AI assistant no longer reports an empty transcript location when you stop a meeting. Mindflow returns control the moment recording stops rather than making you wait for the last few seconds of audio to finish transcribing, so the transcript file is usually written a moment later. That was previously indistinguishable from a failed save. The response now says whether the transcript is finished or still being written, and where it will appear.

## Under the hood

- Meeting counts in the saved file and its companion data file are now derived from the same source, so they cannot drift apart if new kinds of transcript events are added later.
- Crash-recovery files roll over correctly when one meeting is stopped and another started in quick succession from the menu bar.

Existing transcripts keep the counts they were saved with — this release does not rewrite files already on disk.
