# Mindflow v0.7.14

**Released:** 2026-07-31

## What's new

- Starting a recording now tells you it is starting. Clicking Start does not begin recording instantly — Mindflow has to load the speech model and set up audio capture first, and the very first start after launching can take several seconds. Until now the button simply sat there unchanged for that whole time, so a click that was working looked exactly like a click that had failed, and pressing it again did nothing visible either. There is now a "Starting…" state so you can see the click registered and why it is taking a moment.

## Fixes

- An interrupted download of the Arabic Pro model could leave Arabic recording unusable. Arabic Pro arrives as seven files totalling about 2.1 GB, and Mindflow creates its folder as soon as the download starts. If the download was then interrupted — a dropped connection, quitting Mindflow, a full disk — that part-filled folder was mistaken for a finished model. Every attempt to record in Arabic failed with a low-level error about a missing model file, and the Models tab showed Arabic Pro as not downloaded with no way to clear it. Mindflow now treats a model as installed only when all of its files are present. Recording falls back to the compact multilingual model that Mindflow downloads alongside Arabic Pro for exactly this purpose; if the only other models you have are English-only, you now get a clear message telling you to pick a compatible model instead of an unexplained failure. Pressing Download again resumes where it left off rather than starting over.

- When you stopped a meeting, Mindflow could tell your AI assistant the wrong transcript file. Mindflow hands control back the moment recording stops, so the transcript file is written a moment later — and to report where it landed, Mindflow was picking the most recently written transcript in your folder. That is usually the right answer, but not if something else had just touched an older meeting: renaming a meeting, adding a label, moving it to a folder, or the speaker-identification pass finishing on your previous recording all rewrite a file and make it look like the newest one. Your assistant could then be handed a completely different meeting's transcript, reported as successfully saved. Mindflow now identifies the transcript by the meeting's own start time, which is part of the filename, and says nothing rather than guessing when it cannot be certain.

- Speaker labels in Arabic recordings could be slightly misaligned. Mindflow measures a meeting's timeline from the moment recording is ready, and matches that timeline against the separately-recorded audio when it works out who was speaking. On the Arabic Pro engine the timeline was instead being started from the first sound that arrived — up to a couple of seconds later — so speaker labels near the boundary between two people could be attributed to the wrong one. All engines now start the clock at the same point. This affected the other side of the conversation, not your own microphone, and only on Arabic Pro.

- The segment count shown inside a meeting transcript now matches the count stored with it. v0.7.13 corrected the stored count but left the one written into the transcript body, so a transcript could disagree with itself.

## A correction to the v0.7.13 notes

The v0.7.13 notes said that every meeting now gets a crash-recovery file, "however it was started." That was too broad, and we would rather correct it than leave it standing.

Crash-recovery files are written by the connector that links Mindflow to your AI assistant. If you record from the menu bar or the ⌃⌥R shortcut while an AI assistant is connected, you do get one — that is what v0.7.13 fixed, and it was genuinely broken before. But if you record with no AI assistant connected, no crash-recovery file is written. Your transcript is still saved normally when the meeting ends; what you do not get is the in-progress copy that would survive a crash mid-recording.

Extending crash recovery to cover every recording, connected or not, is on the list.

## Under the hood

- The transcript lookup now refuses to answer when two meetings started within a few seconds of each other, rather than picking one. An honest "still being written" is better than a confident wrong answer.
- Added a regression test for the meeting-timeline clock that fails if any future transcription engine forgets to start it.
- Documentation now covers all 24 assistant tools, including the two meeting-summary tools that were missing, and notes that generating a summary needs a local model runner installed.
